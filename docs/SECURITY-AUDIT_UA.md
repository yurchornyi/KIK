# Аудит безпеки KIK — 23 жовтня 2026

## Межі та статус

Перевірено сайт KIK (зараз `kiktv.pages.dev`), його Cloudflare Worker, API, D1, автентифікацію, адмінпанель, синхронізацію, видачу відео, оновлення APK і новий ad scanner. До копії для аудиту включено незакомічені файли та зміни, які з'явилися під час роботи, зокрема нову адмінпанель і Android SearchProvider. Активні зміни об'єднувалися через окрему гілку `codex/security-audit`; вихідна робоча папка не скидалася.

Експлуатаційні тести виконувалися на синтетичних локальних акаунтах і тестових даних. Зовнішні джерела не проходили penetration testing: перевірка відтворення використовувала звичайні запити через власний тимчасовий Worker. Дані реальних користувачів не використовувалися як тестові цілі. Android-проектор, встановлений APK і сервери сторонніх відеопровайдерів не змінювалися.

Статус публікації та підсумкові результати наведено в кінці документа.

## Додаткове посилення

- Вихід використовує такий самий порядок вибору Bearer/cookie, як автентифікація. Поєднання cookie одного входу з Bearer іншого не відкликає неправильну сесію.
- Перевірка Origin і Sec-Fetch-Site поширена на GET API, щоб стороння сторінка не запускала побічні дії GET. Native clients без цих браузерних заголовків підтримуються.
- CSP дозволяє браузерне медіа тільки зі свого origin і blob, а connect — тільки до свого origin. Відповіді з відео мають `private, no-store`; cookies, credentials, Location та CORS headers провайдера не передаються клієнту.
- Медіа не є довільним URL proxy: тільки серверний catalogue adapter може видати квиток. Redirects та HLS URI обмежені дозволеними origin; для перевіреного gateway `stream.voidboost.one` дозволені лише його CDN subdomains. Private IP, локальні домени, HTTP, userinfo та сторонні redirects відхиляються. Lookalike domain також перевірено.
- HLS підтримує variants, maps, ключі шифрування й сегменти. Playlist переписується повністю навіть коли native client надсилає Range; великі списки та невідомі URI variables відхиляються. Медійні bytes передаються потоком.
- Автоматичні redirects metadata providers вимкнено. Паролі, хеші й солі не повертаються приватними API.
- Scanner передає секрет лише на налаштований HTTPS origin, без автоматичних redirects. FFmpeg input protocols обмежені `https,tls,tcp,crypto`; додано timeout, максимальну тривалість і обмеження журналу помилок.
- Ліміти login не блокують вихід. Медіазапити мають окремий ліміт, щоб не витрачати бюджет каталогу.

## Перевірені категорії OWASP

SQL injection: користувацькі значення передаються через D1 bindings; перевірено login, admin search і IDs із SQL metacharacters. Обхід не підтверджений у перевірених маршрутах.

IDOR та access control: sync, settings, profile update, pairing, recommendations, admin users і новий admin usage перевірені з іншого акаунта та без входу. Адміністративні ролі беруться із серверної identity; `role` у запиті не надає прав.

XSS: динамічний текст UI створюється через text nodes; знайдений `innerHTML` містить фіксовану SVG-заставку. CSP забороняє сторонні scripts, frames та objects. Це статичний review та перевірка політик, а не гарантія відсутності всіх можливих XSS.

CSRF: перевірено чужий Origin і Sec-Fetch-Site для змін профілю, sync та адмінпанелі; SameSite/HttpOnly/Secure cookie збережено.

Secrets та infrastructure: `.git/config` і `.dev.vars` на production повертали 404; D1 доступна через binding, публічного SQL endpoint у коді немає. APK update metadata має перевірку репозиторію, пакета, SHA-256, підпису та меж розміру; окремі regression tests пройдено.

## Межі захисту відео та підписок

У цьому проєкті немає власної billing/subscription моделі, тарифів або таблиці платних entitlements. Тому перевіряти «активну підписку KIK» зараз нема за якими серверними даними. Джерельні доріжки з ознакою `premium` залишаються забороненими на сервері; тест підтверджує, що stream adapter навіть не викликається для premium або невідомої озвучки. Premium-доступ не купувався і не обходився.

Власні API та нові медіапосилання KIK контролюють сесію. KIK не володіє стороннім CDN і не може закрити його оригінальні URL, відкликати раніше видані зовнішні посилання чи заборонити перегляд безпосередньо на сайті джерела. Для власного платного відеокаталогу потрібне контрольоване origin storage/CDN із server-side entitlements; за потреби — DRM. Уже отримані авторизованим клієнтом bytes чи запис екрана відкликати неможливо.

Немає заяви про «100% безпечну платформу». Це аудит конкретного коду та набору сценаріїв. Не виконувалися DoS, підбір реальних паролів, зміни даних користувачів, атаки на Cloudflare control plane чи penetration testing чужих CDN. MFA, email verification через поштового провайдера та аудит залежностей за вмістом lock files не впроваджувалися в цій зміні.

## Повторення перевірок

```sh
npm test --prefix web
node --test cloudflare/worker.test.mjs
npm run build --prefix web
npm exec --prefix web -- wrangler d1 migrations apply kik-data --local --config web/wrangler.jsonc
npm exec --prefix web -- wrangler dev --config web/wrangler.test.jsonc --port 8791
# In another terminal:
node web/management-integration.mjs
node web/security-integration.mjs
KIK_LOCAL_FIXTURES=1 KIK_TEST_URL=http://127.0.0.1:8791 KIK_CLEANUP_FILE=work/sync-cleanup.sql node web/integration-test.mjs
npm exec --prefix web -- wrangler d1 execute kik-data --local --config web/wrangler.jsonc --file work/sync-cleanup.sql
```

Для локального відео потрібен окремий випадковий `MEDIA_TOKEN_KEY` у виключеному з Git `.dev.vars`. Production використовує окремий Worker secret. Значення секретів не зберігаються у звіті.

Міграція `0008-security.sql` сумісна з попереднім Worker: додає поля й triggers, не видаляє акаунти чи історію. Чинні акаунти залишаються чинними. Для rollback можна повернути попередню версію Worker, зберігши додані поля D1.

Рекомендації щодо [сесій](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) та [SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) звірено з OWASP Cheat Sheet Series.

## Публікація та підсумкові результати

Код перенесено на гілку `claude/security-audit` (від `claude/studio-intros`). Локально пройдено: 89 unit-тестів, 51 перевірка безпеки, 54 сценарії адмінпанелі, 29 перевірок синхронізації. На тимчасовому Worker MP4 і HLS декодували по 30 секунд відео й аудіо.

Production ще не оновлено. Перед `npm run deploy` потрібно: `wrangler secret put MEDIA_TOKEN_KEY` (окремий випадковий 256-бітний hex) і `wrangler d1 migrations apply kik-data --remote` для `0008-security.sql`.
