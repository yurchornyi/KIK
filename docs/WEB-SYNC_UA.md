# KIK на TV та у браузері

У версії 1.4.0 список і оцінки UASerials синхронізуються окремими ключами джерела. Прогрес його стороннього плеєра KIK не отримує. Старі версії TV продовжують обмінюватися підтримуваними записами основного каталогу.

Для TMDB використовується секрет Worker `kik` з назвою `TMDB_READ_TOKEN`: API Read Access Token або API key v3. Значення не включається в JavaScript, APK чи GitHub. TVmaze й Wikidata працюють без токена.

- Сайт: https://kik.basic-175.workers.dev
- APK: https://github.com/yurchornyi/KIK/releases/latest
- Вебсервер, статичні файли й приватна база D1 працюють у Cloudflare-акаунті **Basic**. Публічний GitHub містить код і APK, а не облікові записи чи історію.

## Підключення TV

1. На сайті створіть обліковий запис через email і пароль від 6 символів і одноразове запрошення адміністратора. Браузер запам’ятовує вхід після закриття вкладки та перезапуску.
2. На TV виберіть свій локальний профіль, відкрийте **Налаштування → Синхронізація профілю → Підключити профіль**.
3. На сайті натисніть **Прив’язати TV**, введіть 8 символів із TV та виберіть спільний профіль. Код діє 10 хвилин і використовується один раз.

Пароль не вводиться пультом і не передається через код. TV отримує власну сесію для облікового запису та прив’язку саме вибраного локального профілю. Інші локальні профілі можна прив’язати окремо. Від’єднання скасовує сесію цього TV; уже завантажені записи залишаються локально.

## Що спільне

Історія, остання серія, позиція та тривалість кожної серії, вибір озвучення, мій список і оцінки «подобається / не для мене». Локальні паролі профілів, кеші, cookies джерела та статистика показів рекомендацій не синхронізуються. Ідентифікатори локальних профілів не замінюються і не відправляються як глобальні ID.

Після першого підключення локальні перегляди об’єднуються з обліковим записом. Кожна серія має окремий ключ, тому перегляд іншої серії не стирає попередні позиції. Нові зміни синхронізуються після збереження прогресу. Головна TV перевіряє зміни кожні 15 секунд, видима вебсторінка — кожні 30 секунд; ручна перевірка доступна на TV. Під час активного перегляду TV надсилає свій прогрес; вхідні зміни застосовуються, коли плеєр не на екрані.

Без мережі зміни залишаються на пристрої та повторюються після відновлення зв’язку. У вебверсії одночасно йде лише одна синхронізація: зміни, зроблені під час неї, і щойно вибраний профіль надсилаються одразу після неї, велика офлайн-черга — частинами по 200 записів. Під час закриття сторінки браузер отримує не більше ~60 КБ (останню позицію перегляду першою), решта чекає наступного відкриття. Якщо сховище браузера заблоковане або заповнене, вебверсія працює далі й показує це в рядку синхронізації. Для одночасного перегляду однієї серії на двох пристроях діє остання зміна за часом. Час пристрою коригується за сервером. Видалення синхронізуються окремими записами, щоб старий офлайн-пристрій не повертав видалене.

## Вебверсія

Адаптивний темний інтерфейс із головним банером, стрічками постерів, пошуком, профілями, історією та моїм списком. Для нового профілю є вибір смаку з можливістю пропустити. Плеєр має вибір озвучення, якості, сезону, серії, швидкості й стандартні повноекранні елементи браузера. Пріоритет озвучень — українська, потім російська. Преміум-доріжки не розблоковуються.

MP4 програє стандартний HTML-плеєр; для HLS у сумісних браузерах використовується HLS.js із локального статичного файлу; він завантажується лише тоді, коли потоку він справді потрібен (Safari грає HLS сам). Доступність конкретної доріжки залежить від джерела; її наявність у каталозі не є доказом доступного відео. Старі браузери, DRM-плеєри й усі моделі пристроїв не перевірені.

Джерело каталогу те саме, що в APK. Для його фіксованого списку доменів Worker використовує HTTPS із перевіркою TLS і обмеженим HTTP-транспортом; редиректи на довільні домени, локальні адреси й незашифрований HTTP не дозволені. Публічного проксі для сторонніх URL немає. Відеофайли не зберігаються у GitHub чи D1.

## Безпека й розгортання

Паролі хешуються PBKDF2-SHA256 з випадковою сіллю та 100 000 ітерацій. Сесії мають випадковий 256-бітний токен; база зберігає його хеш. Браузерна cookie — HttpOnly, Secure, SameSite=Lax. Записи перевіряють власника профілю; запити з іншого сайту відхиляються. Вхід і API мають обмеження частоти. Дані автентифікованих відповідей не кешуються публічно.

Сесія діє до 90 днів і продовжується під час користування в межах 180 днів від входу. Після цього потрібен новий вхід. «Вийти» відкликає сесію браузера. Після закінчення сесії потрібен повторний вхід або прив’язування. Відновлення забутого пароля через email наразі не реалізовано.

Вебкод: `web/`. У цій папці `npm ci`, `npm test`, `npm run build`, `npm run deploy`. Міграції бази: `migrations/`, застосовуються через `wrangler d1 migrations apply kik-data --remote`. Існуючу production-базу не створювати заново. APK збирається з кореня через `scripts/build.sh`, як описано в README. Для API оновлень використовується окремий Worker `kik-updates`.

Перевірки обміну використовують лише тимчасові QA-облікові записи й окремий тимчасовий профіль TV. Оригінальні профілі та історія порівнюються до й після заміни APK та перевірки синхронізації.

Захист медіа, запрошень, відкликання сесій і результати перевірок описано в [SECURITY-AUDIT_UA.md](SECURITY-AUDIT_UA.md). Наявні коротші паролі не змінюються автоматично.
