# Адмінпанель і налаштування KIK

Адміністратор входить звичайною поштою та паролем. Вкладка **Адмінпанель** (`/#admin`) доступна лише акаунтам із роллю `admin` у базі; зараз це один акаунт власника. Інші користувачі цієї вкладки в меню не бачать, а за прямим посиланням отримують пояснення й кнопку «На головну». Роль перевіряється на сервері для кожного запиту; пошта, URL і дані браузера не можуть надати права. Нові акаунти завжди отримують роль `user`. Початкові права надано окремою операцією лише існуючому акаунту власника; публічна міграція не містить його пошти.

## Реєстрація й акаунти

Згори три лічильники: **Акаунти**, **Профілі** і **Чекають реєстрації** (дозволені адреси, з яких ще ніхто не зареєструвався). Кнопка **Оновити** перечитує дані; при кожному відкритті вкладки, якщо дані старші за 15 секунд, вони оновлюються самі. Введений, але не надісланий текст при оновленні не губиться.

- У **Доступі до реєстрації** введіть пошту й натисніть **Дозволити реєстрацію**. Людина може зареєструватися на сайті. Лист автоматично не надсилається — повідомте людину самі. Біля опису видно, скільки адрес використано з 200.
- Якщо адреса вже є у списку, панель так і скаже, а журнал не отримає дубля. Якщо з цією поштою акаунт уже є, дозвіл не потрібен.
- **Забрати дозвіл** закриває майбутню реєстрацію цієї адреси. Для адрес, з яких акаунт уже створено, кнопка називається **Прибрати зі списку**: акаунт працює далі.
- **Акаунти** показано від нових до старих, з кількістю профілів і датою реєстрації; ваш рядок позначено «Це ви». Пошук іде за частиною пошти, під полем видно «Усього» або «Знайдено». **Скинути** повертає повний список, **Показати ще** дозавантажує наступні 100.
- Під кожним акаунтом є маленький показник ресурсів: кількість синхронізованих записів, їхній обсяг у базі KIK і кількість активних входів. Смужка показує обсяг порівняно з найбільшим акаунтом у списку. Натискання відкриває **Ресурси акаунта**: розбивку по профілях (історія й прогрес, мій список, оцінки, вибрані озвучки, AI-добірка) і дату останньої активності. Дані беруться з наявних таблиць D1 під час відкриття панелі, тож Worker не веде додаткового журналу запитів. Перегляд відео йде напряму з джерел і в показник не входить.
- **Профілі** відкриває профілі акаунта з перемикачем покращених AI-рекомендацій. Після закриття вікна журнал оновлюється.
- Для видалення треба ввести пошту акаунта: кнопка **Видалити назавжди** стає активною лише після точного збігу.
- Видалення остаточно прибирає акаунт, його профілі, серверну історію, оцінки, налаштування, сесії та коди прив’язування TV. Також прибирається дозвіл повторної реєстрації. Локально кешовані дані на від’єднаному пристрої не стираються дистанційно.
- Власний акаунт і будь-який інший адміністратор захищені від видалення. **Останні дії** показують 20 останніх змін; для рекомендацій замість технічного ID видно ім’я профілю і пошту. Ліміти списків: 200 дозволених адрес, сторінка зі 100 акаунтів.

Це список дозволених адрес, а не підтвердження володіння поштовою скринькою. Поштові одноразові коди цією зміною не додаються.

## Налаштування

Вкладка **Налаштування** (`/#settings`) містить профіль, параметри браузерного плеєра, фільтр країн, прив’язування TV, завершення інших входів і посилання на APK та джерела даних.

Якість, мова, швидкість і автоперехід серій зберігаються на сервері окремо для кожного профілю й відновлюються в інших браузерах. Без входу вони зберігаються тільки у поточному браузері. Параметри Android TV налаштовуються у самому застосунку; нові браузерні параметри не переписують його налаштування. Фільтр країн залишається локальним для пристрою.

Вибрана вручну доріжка конкретного фільму має пріоритет над загальною мовою. Якщо бажаної якості немає, вибирається найближча нижча; якщо нижчої теж немає — найнижча доступна. Автоматична якість вибирає найвищий доступний потік, без адаптивного оцінювання швидкості мережі.

**Вийти з інших пристроїв** відкликає решту сесій акаунта, включно з TV. Поточний браузер залишається підключеним, історія зберігається. Якщо збережені на сервері налаштування містять застаріле значення, воно замінюється типовим, а решта налаштувань завантажується як зазвичай.

Профіль: **Змінити аватарку**, ім’я з кнопкою **Зберегти**, **Перемкнути профіль**, **Створити профіль**, **Налаштувати смак**. Поки браузер перевіряє вхід, сторінки показують «Завантаження…», а не пропозицію увійти. Зміни у полях плеєра, зроблені до завантаження збережених налаштувань, не перезаписуються.

## Розгортання і перевірки

Спочатку застосовується `0003-admin-settings.sql`, потім оновлюється Worker. Міграція додає роль, таблиці дозволів, налаштувань і журналу; існуючі записи користувачів та історії не видаляються. Права адміністратора не видаються через публічну реєстрацію.

Перевірено 63 unit-тести (серед них серверна логіка адмінки на in-memory SQLite з реальними міграціями) і 53 сценарії адмінпанелі та налаштувань на локальному Worker з реальною D1. Тестові акаунти ізольовані від production. У браузері на десктопі й на ширині 375 px перевірено: дозвіл, дубль, помилку для вже зареєстрованої пошти, пошук і скидання, видалення з підтвердженням, перемикач рекомендацій і журнал, збереження імені й параметрів плеєра після перезавантаження, прив’язку TV і вихід з інших пристроїв (інший браузер і TV втрачають вхід, поточний — ні), вигляд для звичайного користувача.

Локальний повтор:

```sh
npm test --prefix web
npm run build --prefix web
npm exec --prefix web -- wrangler d1 migrations apply kik-data --local --config web/wrangler.jsonc
npm exec --prefix web -- wrangler dev --config web/wrangler.jsonc --port 8791
# In another terminal:
node web/management-integration.mjs
KIK_LOCAL_FIXTURES=1 KIK_TEST_URL=http://localhost:8791 KIK_CLEANUP_FILE=work/sync-cleanup.sql node web/integration-test.mjs
npm exec --prefix web -- wrangler d1 execute kik-data --local --config web/wrangler.jsonc --file work/sync-cleanup.sql
```
