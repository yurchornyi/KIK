# Автооновлення KIK

Код змін і підписані APK зберігаються в [yurchornyi/KIK](https://github.com/yurchornyi/KIK). Сервер перевірки працює в Cloudflare-акаунті **Basic**: [kik-updates](https://kik-updates.basic-175.workers.dev/health).

Застосунок перевіряє релізи після появи головного екрана, не частіше ніж раз на 6 годин. Окреме збережене завдання Android готує оновлення через Wi-Fi кожні 12 годин. Перевірка й завантаження не блокують інтерфейс. Встановлення починається лише на головному екрані або в налаштуваннях; вихід з такого екрана до завершення підготовки відкладає встановлення. Під час перегляду фільму APK лише готується у фоні.

Перед встановленням звіряються розмір, SHA-256, назва пакета, версія, мінімальна версія Android і сертифікат підпису з уже встановленим застосунком. Зниження версії, інший підпис і пошкоджений файл відхиляються. Сервер приймає метадані лише з налаштованого GitHub-репозиторію. У застосунку немає GitHub-токенів.

У налаштуваннях доступні перемикач автооновлення, ручна перевірка і перехід до дозволу Android. Для самостійного встановлення потрібен разовий дозвіл на встановлення пакетів. На сумісному Android застосунок просить встановлення власного оновлення без додаткового діалогу; якщо Android вимагає підтвердження, відкривається системний установник. Відмова не спричиняє безперервних повторних діалогів. Під час заміни APK Android перезапускає процес застосунку.

Старий механізм оновлень вихідної збірки залишається вимкненим, щоб він не перезаписав KIK іншою збіркою.

## Новий реліз

1. Змінити `version_code` і `version_name` в `localization/release.json`.
2. Запустити `bash scripts/build.sh`, `python3 scripts/validate.py` та потрібні перевірки на пристрої.
3. Зберегти перевірені зміни в Git і відправити коміт у GitHub.
4. Підготувати нотатки релізу й виконати `python3 scripts/publish-release.py --publish --notes-file <файл>`.

Скрипт перевіряє сертифікат підпису, версію й пакет, формує `update.json`, створює чернетку релізу, завантажує обидва файли і лише після цього робить реліз доступним як latest. Cloudflare кешує метадані на 5 хвилин; APK завантажується безпосередньо з GitHub Releases.

Збирання потребує локального оригінального APK, розпакованого `decoded/`, Apktool, Android SDK і ключа `work/signing/localization.jks`. Ці вхідні файли, журнали пристрою й дані профілів не входять у Git. GitHub Actions перевіряє код політики оновлень і Cloudflare API; ключ підпису залишається на локальному комп’ютері. Автоматичного створення нових версій коду немає: автооновлення встановлює опубліковані перевірені релізи.

## Як захищено підпис

Ланцюг перевірок, через який має пройти кожне оновлення:

1. **Ключ.** Ключ підпису `work/signing/localization.jks` і його пароль `work/signing/password` лежать лише на комп'ютері власника. Папка `work/`, файли `*.jks`, `*.keystore`, `*.key`, `*.pem` і `*.apk` є в `.gitignore`, а GitHub Actions на кожному push перевіряє, що жоден такий файл не потрапив у Git. В історії репозиторію ключа немає. У Git є лише публічний відбиток сертифіката `localization/signing-certificate.sha256` (SHA-256 сертифіката, з нього не можна підписати APK).
2. **Збирання.** `scripts/build.sh` підписує APK цим ключем (`apksigner sign`) і одразу перевіряє підпис (`apksigner verify`).
3. **Публікація.** `scripts/publish-release.py` читає сертифікат зібраного APK (`apksigner verify --print-certs`) і зупиняється, якщо він не збігається з `localization/signing-certificate.sha256`. Тоді він записує в `update.json` розмір, SHA-256 файлу і `signer_sha256`.
4. **kik-updates.** Worker бере `update.json` лише з останнього релізу `yurchornyi/KIK`, приймає тільки пакет `kik.app`, посилання на APK лише з GitHub Releases цього репозиторію і `signer_sha256`, рівний закріпленому відбитку `SIGNER_SHA256` у `cloudflare/wrangler.jsonc`. Метадані з іншим підписом або без закріпленого відбитка не віддаються й не кешуються (відповідь 503). Тест `cloudflare/worker.test.mjs` перевіряє, що `SIGNER_SHA256` збігається з `localization/signing-certificate.sha256`.
5. **Застосунок.** `AppUpdater` перед встановленням звіряє: `signer_sha256` з метаданих дорівнює підпису вже встановленого KIK; завантажений файл має той самий розмір і SHA-256; у самому APK той самий пакет, версія, `min_sdk` і рівно один сертифікат, який збігається і з метаданими, і з установленим застосунком. Будь-яка розбіжність скасовує встановлення. Нижчу версію застосунок не ставить. Останнім рубежем лишається сам Android: він не замінить застосунок APK з іншим підписом.

Тобто навіть підмінений `update.json` чи APK на GitHub не встановиться без справжнього ключа, який є лише на комп'ютері власника.

**Якщо ключ змінюється** (втрачено чи скомпрометовано): встановлені TV не приймуть оновлення з новим ключем. Потрібно оновити `localization/signing-certificate.sha256` і `SIGNER_SHA256`, розгорнути kik-updates і перевстановити KIK на кожному пристрої вручну.

## Cloudflare

`cloudflare/wrangler.jsonc` задає окремий Worker `kik-updates` у Basic. `worker.mjs` обслуговує `/health`, `/v1/update.json` і `/download`. Зміна API розгортається через `wrangler deploy --config cloudflare/wrangler.jsonc`. Інші Workers не змінюються.
